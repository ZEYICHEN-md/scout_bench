# 投资分析模板（中文版）

> 本模板为华人创始人筛查管线的标准投资分析格式：

---

## 整体结构

每家公司分析包含以下模块（严格按此顺序）：

```
1. 公司标题
   # 公司名
2. 一句话描述（Tagline）
3. 官网链接 + 突出亮点标签（如：AI For R&D | 顶级研究团队 | 明星客户背书）
4. 近期 Trigger 信号（近3个月内的投资触发事件）
5. 基本信息表格（所属赛道 / 创始团队 / 融资信息 / 成立时间与所在地）
6. 公司介绍段落（严格按三句结构，见下文）
7. ## Verdict 主框
   ├─ 市场机会（含竞争格局）
   ├─ 创始人信号
   ├─ 产品（含商业化数据）
   └─ 总评（Tier 评级 + 详细裁定）
8. 创始团队（姓名 + 职位 + 背景描述 + 领英链接）
```

---

## 各章节写法规范

### 1. 公司标题 + 一句话描述 + 官网链接 + 突出亮点标签

```
# 公司名
一句话描述（必须是具体做什么的，不能是空洞的词）

官网：<https://example.com>
亮点：赛道关键词 | 最突出亮点 | 第二亮点 | 第三亮点
```

**示例：**
```
# Panta
Commercial insurance brokerage run by AI agents. Scales like software.

官网：<https://pantainsure.com>
亮点：AI Insurance | 顶级机构背书 | 特险细分市场
```

### 2. 近期 Trigger 信号

**时间窗口**：近 3 个月内的重要投资触发事件。

**触发信号来源**：重磅产品/功能发布 · 新融资宣布 · 商业化突破（ARR、用户数、明星客户签约） · 主流媒体报道 · 社交媒体热度 · 知名大牛/高管加入 · 重大战略合作

写法：只列最重要的 1-3 个信号，每个信号一行，格式：
- `[信号类型]` + `信号内容` + `来源或时间`

**参考格式：**
```
**近期 Trigger**
- 融资：2026年1月完成 $25M Series A，[领投方] 领投，[跟投方] 跟投（来源：TechCrunch）
- 产品：2026年2月发布 v2.0，新增 [功能]，已有 [X] 家付费客户（来源：官网 Blog）
- 高管：前 [Google/Apple/某独角兽] 高管 [姓名] 加入任 [职位]（来源：LinkedIn）
```

### 3. 基本信息表格

基本信息用表格展示，包含四个维度：

| 维度 | 内容 |
|------|------|
| 所属赛道 | 赛道/行业标签（1-3个，如 Insurance AI, B2B） |
| 创始团队 | 创始人姓名 + 职位简称（联创/CEO/CTO） + 过往关键履历背景 |
| 融资信息 | **必须包含时间/年份**。格式：最新轮次 + 金额 + 估值（如有）+ **时间** + 领投方 + 累计。如：`Series A $25M @$150M，2025-07，红杉领投，累计 $45M`。若日期不确定，写最接近的时间段（如 2025年初 / 2025年H1），禁止省略。 |
| 成立时间与所在地 | 成立时间 + 城市, 国家（如 2024 · San Francisco, CA, USA） |

> 表格里只写精简的信息关键词，不详细展开。详细信息放 Verdict 部分。

### 4. 公司介绍段落（核心章节）

公司介绍用 **2–3 个短段落** 呈现，分段逻辑清晰，避免一大段文字堆砌。

**结构规范：**
- **第一段（价值定位）**：说清楚公司核心定位——做什么/解决什么问题/服务什么客户/提供什么价值
- **第二段（突出亮点）**：最能打的成果——融资额/世界纪录/顶级客户/量化指标/商业化数据
- **第三段（创始人背景）**：创始人姓名 + 关键背景（学校/前公司/核心履历）

每段控制在 1–3 句，整体精炼。

**示例**：

```
Elorian 是一个多模态视觉推理研究与产品实验室，目标构建能够像人类一样原生理解和推理视觉信息的 AI。与现有模型将视觉先翻译为语言不同，Elorian 训练模型直接与视觉表征互动和操作。

团队配置堪称硅谷顶尖：是首个由前 LLM 预训练、数据和多模态负责人创立并领导的多模态推理实验室。

创始人 Andrew Dai（CEO）是 Google DeepMind 14 年资深研究员，Gemini 数据联合负责人；联创 Yinfei Yang 是前 Apple 高级主任研究科学家。
```

**禁止**：
- 不要用"根据公开信息""数据显示"等废话开头，直接进数据
- 不要在段落中混入 bullet list 或表格形式

### 6–9. Verdict 主框（四维度合并表格）

**格式**：将市场机会、创始人信号、产品、总评四个维度合并为**一张表格**，替代原来的四个独立小节。

| 维度 | 亮点 | 核心依据 |
|------|------|----------|
| **市场机会** | 强亮点 / 中亮点 / 弱亮点 | **先讲逻辑，数据只作支撑。** 每一点必须是投资判断，而非单纯数字堆砌。逻辑包括：市场结构性痛点（为什么现在）、目标客户与场景清晰度、竞争格局与差异化空间、时机/政策/技术拐点。数据（TAM/CAGR）仅在能支撑上述逻辑时出现，禁止用数据替代推理。<br><br>• [逻辑判断 1：结构性机会或痛点]<br>• [逻辑判断 2：目标客户/场景与差异化]<br>• [逻辑判断 3：时机或竞争格局] |
| **创始人信号** | 强亮点 / 中亮点 / 弱亮点 | • [创始人姓名 (职位)]：[核心履历/成就]<br>• [创始人姓名 (职位)]：[核心履历/成就] |
| **产品** | 强亮点 / 中亮点 / 弱亮点 | • [产品里程碑/商业化数据]<br>• [已签约客户/ARR/用户数]<br>• [技术壁垒/差异化功能] |
| **总评** | **S/A/B/C Tier** | [综合裁定段落：为什么是此 Tier，核心优势、核心风险，最后 1–2 句写退出预期] |

**写法规范**：
- 「核心依据」列内用 `•` 分点，点与点之间用 `<br>` 换行
- 每个维度的依据控制在 **2–4 条**，精炼不堆砌
- 「总评」列写完整段落（5–8 句），不换行分段
- 亮点等级统一使用：强亮点 / 中亮点 / 弱亮点；总评用 Tier 评级（S/A/B/C）

### 10. 创始团队

```
[姓名] / [职位]
[背景描述（一句话，核心标签）]

领英：<linkedin.com/in/xxx>
```

## 格式规范

### 亮点标签（严格使用）

- **强亮点** — 有具体数据/名字/事件支撑的强投资亮点
- **中亮点** — 方向正确但数据不够具体或存在不确定性
- **弱亮点** — 亮点弱、数据不足或存在重大疑虑

### 语言风格

- 用具体数字，不用"很多""不错"等模糊词
- 用名字，不用"创始人A""创始人B"
- 写完整句子，不写 bullet list（Verdict 各节是段落形式）
- **不写"根据公开信息""数据显示"等废话开头，直接进数据**

### 段落结构（每节）

```
[亮点等级]

[第一句：核心判断/结论]
[第二句及以后：数据支撑 + 具体例子 + 差异化说明]
```

## Kickstarter 项目简版模板

Kickstarter 来源的项目通常处于极早期（尚未完成公司化或尚未获得 VC 融资），不套用标准 Verdict 结构，改用以下简版模板：

```markdown
# 【项目名称】Tiiny AI Pocket Lab
官网：<https://example.com>（如有）
【产品】口袋级本地120B LLM推理设备，提供私密、无需云端的本地化AI运行体验。
【核心卖点】全球首个可于口袋级设备上运行高达1200亿参数（120B）大模型的本地AI设备。
【众筹表现】截至4月初，众筹金额已接近300万美元，获得超过2000名支持者。上线仅5小时，众筹金额便突破100万美元。
【公司状态】20XX年X月已成立公司
【团队】CEO [姓名]，前[公司][岗位职级]，全职团队5人。上海交大团队孵化
【交付预期】2026年8月
【追踪建议】公司化已完成，建议交付后立即接触，预判天使轮窗口
```

**公司化/团队信息查证优先级**：
1. 中国内地项目 → 天眼查 / 企查查
2. 海外项目 → Crunchbase / OpenCorporates
3. 创始人 LinkedIn "About"/"Experience" 是否标注公司名
4. **公司官方 LinkedIn 页面**（验证公司存在、团队规模、动态更新）
5. **公司官网**（如有，优先放在项目名称下方）
6. 媒体报道 / 众筹页面 FAQ
7. 均查不到时，明确标注"公司注册信息未公开"，并基于已有信息给出追踪建议
